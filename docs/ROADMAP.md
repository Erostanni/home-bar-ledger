> 目标周期：4 周 / 约 30 个工作日

## 0. 结论先说

**推荐路径：把"单文件应用"重构成"共享内核 + 三个壳"。**

```
                    ┌─────────────────────────┐
                    │   core/  纯逻辑内核      │
                    │  库存·扣减·成本·账单聚合 │  ← 无 DOM 依赖
                    │  （唯一真源，可单测）    │
                    └───────────┬─────────────┘
                                │
        ┌───────────────────────┼───────────────────────┐
        │                       │                       │
   ┌────▼─────┐          ┌─────▼──────┐         ┌──────▼──────┐
   │ 单文件版  │          │  Web/PWA   │         │  Android    │
   │.standalone│          │ index.html │         │ Capacitor   │
   │ .html     │          │  + SW      │         │   壳        │
   │ 双击即用  │          │ + Pages    │         │ + 自动更新   │
   └──────────┘          └────────────┘         └─────────────┘
```

为什么这么拆：

- **"更新化"**要求数据与代码分离——加配方时只推 `data.json`（~250KB），不让用户重下整个应用
- **"手机版"**要求逻辑能脱离 DOM——Capacitor 壳直接复用 `core/`，不重写一行业务逻辑
- **"双击即用"是这个产品的独特卖点**，不能因为要做 PWA 就丢掉 → 单文件版作为一等公民保留

**一个必须先解决的法律问题**（详见 §5.1）：上游 954 张配方图来自 **262 个不同版权方**（Punch、Imbibe、Liquor.com、Epicurious…），MIT 协议只覆盖 JSON 数据，**不覆盖图片**。直接打包进公开仓库 = 侵权。

## 2. 需要你拍板的 3 件事

> 这三个都会实质改变排期，越早定越好。

### 决策 A：手机版做到什么程度

| 方案 | 周期 | 分发 | 代价 |
|---|---|---|---|
| **PWA（可安装到桌面）** | 1 周 | 网址 / QR | 无应用商店，但加到主屏后体验接近原生，**零审核** |
| **PWA + Android APK** ← 推荐 | +3 天 | GitHub Releases / 应用商店 | 需 Android SDK，**用 GitHub Actions 打包，本地不用装环境** |
| **+ iOS** | +2 周 | App Store | 需 Mac + $99/年账号 + 证书。**一个月内做不了，建议推到 v2.1** |

**我的建议**：W3 做 PWA，W4 用 Capacitor 出 Android APK（CI 出包），iOS 排 v2.1。
→ 需要你确认：**你有没有 Mac？** 有的话 iOS 可以挤进 W4；没有就别碰。

### 决策 B：配方图片怎么办

| 方案 | 成本 | 风险 |
|---|---|---|
| **不上图**（现状） | 0 | 0 —— 但 44MB 的资源白白浪费，产品质感少一档 |
| **AI 生成统一风格插画** ← 推荐 | 2–3 天 + 生成成本 | 0，版权完全自有，风格统一 |
| 用上游 954 张图 | 0 | ⚠️ **侵权**（262 个版权方） |
| 只用标 CC 的图 | 0 | 可用图太少（原料图仅 15 张标 CC） |

**我的建议**：AI 生成 663 张**统一风格**的鸡尾酒插画（扁平/暗调酒吧风，480×640，~20KB/张，共 ~13MB）。

> **2026-10-23 更新**：本项**暂缓**。用户决定当前不考虑图片，
> 图片生成管线与已生成的图均已从仓库移除（`build/gen_images.py`、`assets/`）。
> 管线方案在此留档备查，需要时可按同样思路重建。
→ 需要你确认：**要不要花这个钱/时间？** 不要的话就保持纯文字，我把这 3 天挪去做别的。

### 决策 C：单文件版是否继续维护

继续维护 = 每次改功能要同步改两套构建。成本约占总工作量 15%。
**我的建议**：继续维护，但**只同步功能，不同步优化**（单文件版只保证功能可用、界面不过度美化），把美化投入全给 Web 版。

### Week 3 — PWA + 自动更新

**PWA 基础**
- `manifest.webmanifest`（名称、图标、主题色、`display: standalone`、快捷方式）
- 3 种尺寸图标（192 / 512 / maskable），程序化生成
- Service Worker：app shell 预缓存、离线可用
- 「添加到主屏」引导（iOS Safari 需单独提示，Chrome 可用 `beforeinstallprompt`）

**自动更新机制**（核心需求）

```
version.json  { version, dataVersion, releasedAt, notes, minCompat }
     │
     ├─ 页面启动时 fetch（带时间戳绕过缓存）
     │    └─ 版本不一致 → 顶部弹出更新条 → 用户点"立即更新"
     │         → postMessage 给 SW → sw.skipWaiting() → location.reload()
     │
     ├─ 后台每 30 分钟再查一次（静默，仅在有新版本时才提示）
     │
     └─ SW 缓存策略
          app shell (index.html/app.js/core.js/styles.css) → stale-while-revalidate
          data.json                                          → stale-while-revalidate（先给旧，后台拉新）
          配方插图                                           → cache-first + 容量上限清理
```

**关键收益**：加 100 款配方只需推 `data.json`（~250KB），代码不动，用户下次打开自动更新。**1MB 的应用本体也不用重下。**

**版本策略**
- `SemVer`：`v1.2.0` = 功能，`dataVersion` 独立递增
- 每次发布生成 `CHANGELOG.md` 条目 + GitHub Release + tag
- 保留降级路径：数据格式变更时 `minCompat` 拦截，旧壳不加载新数据

**Week 3 验收**
- [ ] 断网后完全可用（所有 4 个页面）
- [ ] 改 `version.json` → 前台 1 分钟内出现更新提示

## 5. 风险与对策

### 5.1 ⚠️ 图片版权（最高优先级）

**事实**：上游 954 张配方图来自 **262 个不同版权方**——Punch Staff（114 张）、Imbibe Magazine（41）、Liquor.com（39）、TuxedoNo2（27）、Reddit（25）、The Spruce Eats、Epicurious、Steve the Bartender，以及大量个人摄影。**每个文件都在 JSON 里记着 `copyright` 字段**——这恰恰说明上游并不拥有这些图，MIT 协议覆盖的是 JSON 数据结构而非图片。

**风险**：打包进公开 GitHub 仓库 = 二次分发受版权保护的图片。个人小站风险低，**公开仓库 + 应用商店 = 可被追责**。

**对策**：
1. **默认不上上游图片**（v2.0 主线）
2. 若要图 → **AI 生成统一风格插画**，版权 100% 自有
3. 若必须用上游图 → 只进私有部署，绝不进公开仓库/商店
4. 任何情况下在 `LICENSE` 和 README 里保留上游出处与 `data/LICENSE`

### 5.2 翻译质量

- 建**术语表**（`translations.py` 顶部固定映射），杜绝同物异译
- 每批 10% 抽样人工复核
- 描述类文本允许意译，步骤类文本要求直译（步骤错了会做错酒）
- 保留英文原文（`descEn`/`stepsEn`），用户可对照 —— 长尾配方可省英文原文省体积

### 5.3 范围膨胀

- W2 的 P0/P1 清单**现在就冻结**，新增需求进 v2.1 backlog
- 每周五做一次「本周没做完的砍掉」复盘
- 配方图片是唯一可整块砍掉的大项（决策 B）

### 5.4 更新机制把用户搞崩

- 数据结构变更必须带 `minCompat`，旧壳不加载不兼容数据
- 保留 `hbl.v1` localStorage 键，跨版本读同一个键
- 首次启动写 `db.schemaVersion`，升级时跑迁移函数
- **永远保留单文件版作为逃生舱**：PWA 出问题，用户还能下 232KB 的 HTML 手动用

### 5.5 iOS

一个月内不承诺。需要 Mac + $99 账号 + 证书 + 审核周期。**列入 v2.1**。
